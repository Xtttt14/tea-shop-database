# 第一周：经营场景与业务需求

## 1. 项目定位与边界

项目名称：茶序奶茶店经营管理系统。服务一家校园周边奶茶店，销售现制饮品，面向到店顾客和线上会员。数据库需记录商品、原料库存、订单、订单明细、会员、员工，以及配送、优惠券、充值和支付。

支持自营线上商城点单、到店收银、自提与门店安排的外卖配送。不对接美团等第三方平台。阶段一用SQL模拟商城和支付业务；真实网页与接口在后续阶段实现，不将“有线上订单记录”等同于“已有可用商城”。

复杂度控制：单门店、单币种人民币；商品按固定杯型定价、固定配方扣料，温度与糖度只作制作备注，本版不改变标准用量；不支持任意加料。每单最多使用一张满减券；储值不赠送金额，不计息、不转账；订单使用一种支付渠道，不混合支付；配送由门店人工指派一名骑手，不做地图路径优化。阶段一退款仅支持整单退款，不支持部分退款。

## 2. 角色与职责

| 角色 | 职责 | 权限边界 |
| --- | --- | --- |
| 普通到店顾客 | 选择饮品、确认金额、付款、取餐 | 无需登记个人身份，不享受会员券和储值 |
| 会员/线上顾客 | 浏览商品、下单、维护地址、领券、充值、使用余额、查自己的订单和积分 | 仅访问自己的资料与资产；线上下单须登录 |
| 收银员 | 代客下单、关联会员、核对金额、确认支付和取餐 | 不可改库存成本、券规则和会员余额；数据库写入由受信任业务执行者完成 |
| 制作员 | 查看已付款制作任务，制作饮品，反馈完成或制作失败 | 只需要饮品选项和数量，不需要会员余额或配送地址 |
| 库存管理员 | 验收入库、检查到期、盘点、登记损耗和补货需求 | 不访问会员资金资料，不改成交价格 |
| 骑手 | 查看分配的配送单、接餐、配送、确认送达或异常 | 只应看到自己任务所需的收件信息 |
| 店长 | 维护商品配方、员工职责、优惠券规则，审核退款、报损和充值异常，查经营统计 | 普通业务管理不等于数据库管理员 |
| 数据库管理员 | 建库、授权、备份及技术维护 | 技术管理角色，不作为日常收银账号 |

一名员工可兼任收银和制作，实际应用可为同一用户授予多个角色。成员分工与经营角色是不同概念。阶段一数据库演示员工角色级授权；会员和骑手的逐人数据隔离留到应用身份映射阶段，不直接向他们开放数据库登录。

## 3. 从下单到交易完成

1. 店长维护商品、杯型、价格、标准配方及上下架状态；库存管理员登记原料入库。
2. 到店顾客由收银员录单；线上会员登录自营商城，选择商品、杯型、糖度、温度与数量。
3. 选择自提或配送。配送必须提供收件人、电话及地址并确认位于门店服务范围；保存本次地址快照，后续修改个人地址不改变历史订单。
4. 核对原料可用量（现存量减预留量），不足时提示更换商品。确认订单时预留原料；同一件原料不可重复分配给多笔待支付订单。
5. 选择可用券并校验归属、有效期、最低商品金额；暂时锁定此券。商品总额减券优惠加配送费得到应付金额。券不抵扣配送费；自提配送费为0。
6. 选择现金（仅柜台）、外部支付或会员余额。余额不足时整单改用其他渠道，或先完成充值。支付处理中不重复发起扣款；超时需核对支付结果，不能简单当作未付款。
7. 支付成功后记支付结果、核销券；余额支付同时登记储值扣款流水。将预留原料转为实际耗用并记录库存变动，订单进入制作队列。重复支付通知不得再次扣余额、扣库存或核销券。
8. 制作员按订单明细制作。额外原料损耗另外登记，不修改标准销售耗用记录。
9. 自提：出餐→核对取餐信息→交付。外卖：出餐→指派骑手→骑手取餐→配送中→送达确认。
10. 订单完成后累计积分，暂定按商品实付金额每满1元计1分（不含配送费，不计充值）；保留积分变动记录。

## 4. 配套与异常流程

| 场景 | 处理流程与数据影响 |
| --- | --- |
| 充值 | 会员选择金额→创建充值记录→外部支付确认→增加余额并写充值流水；失败不加余额；同一外部流水只入账一次 |
| 领券 | 店长创建券活动→向会员发券→记录归属与状态；同一活动每人一张，券规则发布后不直接修改已发券语义 |
| 未付款取消/超时 | 核实没有成功支付→关闭订单→释放原料和优惠券预留，不产生退款和积分 |
| 已付款取消 | 店长审核→整单按原渠道退款→记录退款结果；余额支付退回会员余额；未实际耗用原料才恢复库存，已制作的饮品登记损失 |
| 券退回 | 全额退款成功后解除核销；仍在有效期内可重新使用，过期则不可再次使用；保留原订单优惠快照 |
| 完成后退款 | 撤销该订单已发积分，保留冲正流水；本版不支持积分消费，避免负积分处理扩展 |
| 配送失败 | 记录原因与联系处理结果；可安排重新配送或审核整单退款，不能直接标记已送达 |
| 补货/盘点 | 验收入库记正向变动；损耗记负向变动；盘点有差异时记录原因和审核结果，不覆盖历史流水 |
| 外部结果不明 | 保持待核对状态，由店长核对支付或退款结果，禁止以重复操作代替核对 |

## 5. 数据边界：进库

| 数据 | 主要内容 | 原因 |
| --- | --- | --- |
| 商品 | 名称、杯型、售价、售卖状态 | 支持统一点单和定价 |
| 原料、配方与库存 | 单位、标准用量、现存量、预留量、库存变动 | 现制饮品库存应管理原料，支持缺料判断与追溯 |
| 订单 | 渠道、履约方式、会员、经办员工、时间、状态、商品金额、优惠和配送费 | 追踪完整交易 |
| 订单明细 | 商品及名称/规格快照、数量、成交单价、糖度、温度 | 历史订单不能随商品改名调价而变化 |
| 会员 | 会员编号、必要联系方式、积分与变动 | 关联订单和会员权益 |
| 员工 | 编号、姓名、主要职责、在职状态 | 追踪经办与权限依据 |
| 优惠券 | 活动规则、有效期、会员领券记录、状态与使用订单 | 防止重复使用或使用他人优惠券 |
| 储值 | 当前余额、充值/消费/退款流水及外部参考号 | 能解释余额来源，避免重复入账 |
| 支付/退款 | 渠道、金额、结果、原支付关联、参考号 | 对账与退款追溯，不保存支付凭据秘密 |
| 配送 | 订单地址快照、收件方式、骑手、状态、出发/送达时间、异常原因 | 支持履约与异常跟进 |

## 6. 数据边界：不进库或本版暂不进入

| 数据 | 决定 | 原因 |
| --- | --- | --- |
| 支付密码、完整银行卡、支付平台密钥 | 不作为业务数据存储 | 由支付服务处理；配置秘密不提交Git |
| 身份证、生日、学校班级、顾客健康资料 | 不收集 | 完成购买不需要 |
| 非会员到店顾客姓名和电话 | 不收集 | 现场交付不需要身份信息 |
| 浏览轨迹、广告画像、聊天录音 | 不进入 | 本版聚焦交易，不做营销画像 |
| 骑手持续GPS轨迹与路线算法 | 暂不进入 | 只记录关键配送节点即可支持本项目 |
| 第三方外卖平台内部数据 | 暂不进入 | 采用自营商城与门店安排配送 |
| 供应商合同、工资、水电、税务 | 暂不进入 | 不建设完整财务和人事系统 |
| 多门店调拨、自动采购预测 | 暂不进入 | 当前单店，后续课程再增加分析能力 |
| 原料批次与效期明细 | 阶段一暂不进入 | 本版按原料汇总库存，现场检查效期并记录损耗；不能声称已有批次追溯 |
| 真实顾客资料 | 不提交仓库 | 实验样例全部虚构 |

## 7. 第一周小组确认事项

已由用户明确：奶茶店场景、外卖配送、线上商城、优惠券、储值服务。本文其余金额、积分和退款等细则为可解释的设计假设，待组员讨论确认；没有虚构访谈或人工验收。组员需重点解释：原料与商品区别、券与余额区别、订单金额与充值收入区别、配送失败与订单完成区别。
